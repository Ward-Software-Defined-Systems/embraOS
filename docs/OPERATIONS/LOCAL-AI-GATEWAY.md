# Routing the providers through WSDS Local AI Gateway

[WSDS Local AI Gateway](https://github.com/Ward-Software-Defined-Systems/Local-AI-Gateway) is a monitoring, inspection and data-loss-prevention reverse proxy for LLM traffic: a separate WSDS project that runs beside embraOS, never inside it. Its unified listener takes the standard Anthropic, Gemini and OpenAI-compatible paths and forwards each request, byte for byte and with the key the client sent, to the provider the path names. embraOS routes every provider request through it with one command, `/local-ai-gateway`, and back with another.

**Status.** Under evaluation (2026-10-25). The operator is evaluating the gateway as the companion of embraOS and for vendoring into this workspace, the way WardSONDB was vendored at `crates/wardsondb`. The unified listener, the cloud backends and HTTPS are on the gateway's `main` since 2026-10-25. Since the gateway's `d24dc9a` and `658fe29` every proxy-listener response carries `x-local-ai-gateway: <version>`, and a listener can serve HTTPS from the gateway's own certificate authority; embraOS requires the header before it stores a URL, and trusts the CA through the operator's drop-ins. The live checks of this page are listed at the end; a row marked TBD has not been run.

## What the gateway does with a request

- **Forced routing by prefix.** The brain sends every request with the gateway's own prefix for the provider: `/anthropic/v1/messages`, `/gemini/v1beta/models/<id>:streamGenerateContent?alt=sse`, `/ollama/v1/chat/completions`, `/lmstudio/v1/models`. The gateway strips the prefix and forwards the rest of the path and the query to that backend, whatever the model is called (`crates/gateway-proxy/src/route.rs`, `strip_provider_prefix`). Nothing is translated: Anthropic Messages, Gemini `generateContent` and the OpenAI-compatible chat reach their provider in their own format.
- **The key stays the brain's.** The gateway holds no provider keys. It forwards `x-api-key`, `x-goog-api-key` or the preset's bearer to the backend the prefix names and to nothing else, and redacts them in what it stores.
- **Recorded.** Every inference request is a row in the gateway's Requests tab: both bodies (redacted), the headers, the chunk timeline, tokens, time to first token, how it was routed, copy as curl. Cloud traffic is priced at list rates on the Cloud tab. Bodies are kept 7 days by default, in the gateway's SQLite database on the gateway host; the system prompt and the knowledge-graph context of every turn are in them. A request without a body — the probe's `GET /v1/models/<id>`, the key check, `/model`'s list, `/api/ps` — is a `passthrough` row (`router.rs::classify` makes every non-POST one): forwarded unread, recorded as metadata only (method, path, status, timing, `routed by`, no model), kept 24 hours by default (`passthrough_retention_hours`), and listed only with the Requests tab's `passthrough` filter ticked. A cloud-bound POST outside the inference formats — Gemini's `cachedContents` — is a `cloud_passthrough` row: buffered, scanned and stored with its bodies like inference, but no usage is parsed from it, so it has no tokens, no price and no place on the Cloud tab or in the metrics, which cover the parsed inference formats only. `POST /v1beta/interactions` (`image_generate`) is one of those formats since the gateway's `471d93f` (`gemini_interactions`: the model read from the body, the usage from the response, the image models priced in their own rows); on a gateway before it, the request was a `cloud_passthrough` row.
- **Scanned.** Request bodies are scanned for secrets and personal data before they leave. On a cloud provider a secret **blocks** the request: the gateway answers 403 with the header `x-gateway-blocked: dlp` and a body in the provider's own error shape whose message is `request blocked by gateway DLP policy (rule <id>)`. embraOS shows that body as the turn's error (`HTTP 403: …`); the Security tab shows the finding with its JSON path into the request, such as `$.messages[3].content`. Headers are not scanned, so the probe and the key check, GETs without a body, are never blocked.
- **Streams pass through.** A 2xx body is forwarded chunk by chunk, never buffered; a client that hangs up drops the upstream stream, so `/stop` ends a generation through the gateway as it does direct. The gateway never follows a provider's redirect and sends none of its own on the proxy listeners.
- **Identified.** Every response from a proxy listener carries `x-local-ai-gateway: <version>` (the gateway's crate version, `0.1.0` today), set after the gateway's handler, so it is on a proxied stream's head, on the merged model list and on every refusal; a header of that name from an upstream is replaced. `/local-ai-gateway <url>` and `on` read it from `GET <url>/v1/models`, the gateway-generated merged list, which the gateway does not record, and refuse a listener without it.

## Setting it up

On the gateway host, in `config.toml` (`local-ai-gateway config init` writes one with every default):

- `[unified] listen` must name a non-loopback address, such as `"0.0.0.0:4000"`; the default `127.0.0.1:4000` is unreachable from the OS. The proxy listeners carry no authentication; bind them to a network you trust, and give the unified listener HTTPS (next bullet) so the provider key does not cross it in clear. On a first boot the wizard asks for the gateway right after the name step, so for an `https://` listener the CA is seeded before that boot.
- `[unified] tls = "on"` serves HTTPS on the same port, with a certificate from the gateway's own certificate authority: `tls/ca.pem` in its data directory, minted at the first start; the server certificate, reissued at every start, carries `localhost`, the loopback addresses, the host name, the listeners' addresses and the names in `[tls] sans`. The name embraOS uses in the URL must be one of them (`[tls] sans` adds it; a restart item). Export the CA on the gateway host, `local-ai-gateway tls ca-cert > Local-AI-Gateway_ca.pem` (or download it from the Settings tab; `tls show` prints the fingerprint to compare), and seed it into the OS's CA drop-ins with the VM stopped: `./scripts/seed-state.sh --ca-dir <directory holding the .pem>` ([BUILD/QUICK-START.md](../BUILD/QUICK-START.md#self-hosted-git-servers-private-ca)). Every HTTP client of the brain trusts the drop-ins in `/embra/state/ca-certificates/` beside the stock roots, read once at the first client a boot builds, so a seeded certificate takes effect at the next boot; the boot journal counts them (`operator CA drop-ins: N certificate(s)`). The URL is then `https://<host>:4000`: `https://` keeps its implicit 443, so the port is given.
- Each backend embraOS uses is `enabled`, and its `upstream` is the server that should answer: `[backends.anthropic]` and `[backends.gemini]` default to the providers' hosts; `[backends.ollama]` and `[backends.lmstudio]` default to `http://127.0.0.1:11434` and `http://127.0.0.1:1234` **on the gateway host**, not to the endpoint stored in embraOS.
- `[dlp.cloud] request_action` is `block` by default. The Security tab's test box shows what a text would trigger.

From an embraOS instance in QEMU, the host machine is `10.0.2.2`, and a name such as `axiom-app.ops.wsds` resolves through QEMU's forwarder at `10.0.2.3` when the host resolves it.

## `/local-ai-gateway`

| Command | Effect |
|---|---|
| `/local-ai-gateway` | Show the gateway: whether one is stored, its URL, and whether requests go through it |
| `/local-ai-gateway <url>` | Store the unified listener and turn it on, once it has identified itself. The URL is normalized first: a bare host gets `http://` and `:4000`; `https://` keeps its implicit 443; a trailing `/` is dropped; a path is kept; a loopback host, a query or credentials in the URL are refused with the reason. Then `GET <url>/v1/models` must answer with the gateway's `x-local-ai-gateway` header: a listener that does not answer, or answers without it (another gateway, a plain model server, a gateway from before the header), is refused with the reason, and nothing is saved. A certificate the brain does not trust is refused naming the drop-in directory; a TLS listener given as `http://` is refused naming `https://`. The Info names the gateway's version |
| `/local-ai-gateway on`, `/local-ai-gateway off` | Turn the stored gateway on, after the same identification, or off; the URL is kept |
| `/local-ai-gateway reset` | Forget the gateway |

A change is saved to `SystemConfig.provider_gateway` (serde-additive; an instance from before the field reads as not configured) and takes effect on the next message: the provider is rebuilt from the configuration at every turn start. The health probe runs through the new route at once; `/status` and the web console's provider pill show its result, and the probe's `endpoint` names the host reached: `api.anthropic.com` direct, `axiom-app.ops.wsds:4000` through the gateway. `/provider` adds `Gateway: on (<url>)` or `Gateway: off (<url> kept)` to its status line. The web console shows a `local-ai-gateway` pill while a gateway is stored: green while every provider request goes through it, grey while it is off, gone after `reset`; its tooltip carries the URL. `/status` carries a `provider_gateway` block with the URL and the switch. The first-boot wizard asks for the gateway right after the name step, with the same normalization and identification (a refused URL is asked again, and `direct` falls back to reaching the providers directly); that boot's key check and a preset's model list go through it.

## What goes through, and what stays direct

| Provider | Prefix | Through the gateway while it is on |
|---|---|---|
| Anthropic | `/anthropic` | `POST /v1/messages` (every turn, the learning turns, the replicant check); `GET /v1/models/<id>` (the probe); `GET /v1/models` (the key check of `/provider --setup anthropic`) |
| Gemini | `/gemini` | `POST /v1beta/models/<id>:streamGenerateContent?alt=sse`; `POST` and `DELETE /v1beta/cachedContents…` (the explicit cache of Gemini 3.1 Pro); `GET /v1beta/models/<id>` (the probe); `GET /v1beta/models` (the key check); `POST /v1beta/interactions` (`image_generate`) |
| Ollama | `/ollama` | `POST /v1/chat/completions`; `GET /v1/models` (`/model` and the probe); `GET /api/ps` (the probe's context-window reading) |
| LM Studio | `/lmstudio` | `POST /v1/chat/completions`; `GET /v1/models` (`/model` and the probe) |

Ollama and LM Studio keep the endpoint stored in embraOS; the gateway's `[backends.<name>] upstream` is the server that answers while the gateway is on, and the stored endpoint is used again when it is off. `/model` lists the models the gateway's upstream serves.

Direct, whatever `/local-ai-gateway` says: the Guardian tools (`web_search`, `http_request`, `http_get`), which have their own egress rules (`/guardian egress`); the sentence-embedding model, which runs inside the OS and sends nothing. The wizard's key check and preset probe are direct only when its gateway step chose direct.

## Caveats

- **The provider key reaches the gateway host in clear over `http://`.** The brain says so when `/local-ai-gateway` stores an `http://` URL. Over `https://` the key is covered on the way: the gateway's own CA among the operator's drop-ins (above), or a publicly trusted certificate on a reverse proxy in front of the gateway, which needs no drop-in. A listener whose certificate the brain does not trust is refused at `/local-ai-gateway <url>`, before anything is saved.
- **Bodies are stored on the gateway host.** Redacted of what the DLP rules match, kept 7 days, in an unencrypted database. Treat the gateway's data directory as you treat embraOS's DATA.
- **A block is a failed turn.** The turn ends with the 403 and the rule's name; nothing was sent to the provider. A memory or a tool description that matches a rule blocks every turn until the finding is allowlisted on the gateway (`[[dlp.allowlist]]`) or the text changes. A block is never mistaken for a stale Gemini cache: the stale-cache retry fires only on a body that names a cached content. A blocked `cachedContents` creation makes the turn go uncached, and the stream request then names the rule.
- **A toggle is a new probe target.** The probe announces a standing failure once more after a toggle, says nothing on a healthy flip, and reads Ollama's context window again at its next run.
- **A preset set up through the gateway may have no direct endpoint.** While the gateway is on, `/provider --setup <ollama|lm_studio>` and the wizard's sub-flow list the models through the gateway's prefix and store the endpoint typed, unprobed, as the direct path for when the gateway is off; `none` (the default when nothing is stored) stores no endpoint. Such a preset answers only while the gateway is on: `/local-ai-gateway off` and `reset` say so, and a turn on it, `/provider <kind>` and the probe refuse it until `/provider --setup <kind>` stores an endpoint or `/local-ai-gateway on` brings the gateway back (`OpenAiCompatConfig::for_preset_routed`, the one readiness rule). A probe that fails through the gateway names its `[backends.<prefix>] upstream`, which must answer.
- **The gateway's own limits apply.** Requests are buffered in full with a 64 MiB cap (413 above it); open streams are cut five seconds into a gateway shutdown; the unified listener's `default_backend` never sees a request from embraOS, because every one carries a prefix.
