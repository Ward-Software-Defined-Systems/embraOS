# Command Reference

Every slash command available in an embraOS session, grouped as in the web console's sidebar (the chat-mobile picker and the console `/help` use the same groups). See also [Keyboard Shortcuts](OPERATION.md#keyboard-shortcuts).

Before a session exists (the first-boot configuration wizard, Learning Mode and the identity import's dialogue) six commands are answered: `/backup` and `/reboot` (a machine that was installed again is restored from there), `/ca` (a certificate authority of the operator's own, the provider gateway's among them, is imported ahead of the provider's setup), `/network` (a machine on a network without DHCP is given its address there, from its own display or its serial line), `/theme` (the look of the console the setup is answered in) and `/web-token` (a console URL that someone else has seen is replaced there). Any other command gets one line, `Not run: <command>. Commands are answered once setup is complete …`, and the four the console answers itself (`/help`, `/ml`, `/media`, `/show-tools`) work as always, as does `/stop`. A command is typed at a question that takes text, or in Learning Mode: while a list of choices is on the screen, Enter sends the highlighted choice.

## Session

| Command | Description |
|---|---|
| `/sessions` | List all sessions, most recently active first, with state, the provider each session is pinned to, turn count, and last active time (configured timezone). When a session is pinned to another provider than the active one, a closing line gives the steps to open it |
| `/new <name>` | Create a new named session and switch to it; the transcript starts empty (the web console and the mobile chat clear what they showed). Duplicate names are refused (`/switch` to attach an existing session; a soft-deleted name stays reserved through its grace period). A name is `[A-Za-z0-9][A-Za-z0-9_-]{0,63}`; anything else is refused with the reason, since the name becomes a database collection |
| `/switch <name>` | Switch to an existing session: the transcript is replaced by that session's history (rows marked `history`, images and files included), then the intelligence briefs itself on what happened while away (once the soul is sealed, in a session that has history) |
| `/close` | Close the current session |
| `/sessions delete <name>` | Guided deletion: the intelligence summarizes the session, asks your reason, and preserves durable memories to the knowledge graph as memories of that session; your reply is the approval. The system then soft-deletes it and records the deletion and your reason as a memory linked to what was kept (7-day grace period; any slash command mid-flow cancels, but for the four the console answers itself and `/stop`; the `learning` session is never deletable) |
| `/sessions restore <name>` | Undo a soft delete during its grace period (the session returns Detached — `/switch` to attach) |

## Turn

| Command | Description |
|---|---|
| `/ml` | Open a multi-line message editor. **Web console (default):** from the sidebar or the command palette, a textarea modal — Ctrl/⌘+Enter or **Send** to submit, Esc/Cancel to discard; sent verbatim as one message (a body of one line is sent as if typed: trimmed, and a command when it starts with `/`). Typed into the web terminal, `/ml` toggles the dot-terminator mode of the serial TUI. A multi-line paste from the clipboard into either console's input does the same without the editor: it is staged whole with what the input box already held, shown as a preview, and Enter sends it with anything typed after it as one message, verbatim; Backspace on an empty input drops it; a one-line paste, its final line break included, is typed into the input. **Serial TUI (`EMBRA_TUI=1`):** toggles dot-terminator mode — type lines, `.` on its own line to send; a clipboard paste is staged as in the web console, one message however many lines |
| `/stop` | Stop a stuck in-flight turn (local models can loop in unbounded reasoning). Console: type it or press **Esc** while the turn runs (while a model server reads the prompt, while it answers, while a tool runs); mobile: the ■ button that replaces Send while busy. The partial response is kept, marked `(response interrupted by operator stop)`; on screen it lands once, with the warning under it. A turn stopped before any text is recorded as `(turn stopped by operator)`, which the intelligence reads on its next turn as a note inside your message, never as a reply of its own |
| `/continue` | Send the last call of a turn that was cut once more. A turn is cut when a model call fails before the turn has finished: the request is refused or lost, the model server sends nothing for the whole [model wait](#model), or the stream breaks. The turn is saved as far as it got (the operator's message, the reply so far, a marker), and the call that failed is kept in memory with everything the turn held: the tool results and the model's earlier steps, which a history does not keep. `/continue` sends that call again as it was; the reply is saved after the cut turn, under the row `[continue the turn that was cut]`. One cut turn is kept, the machine's last: a turn cut later in any session takes its place, and in another session `/continue` names the session to switch to. It needs the provider and model the turn ran on, and it is refused once a message of the operator's has followed the cut, the brain has restarted or the session is deleted. Then, as after any cut, the next turn is told what was cut and which tool calls had finished |
| `/iter-cap` | Show the current per-turn tool iteration cap (default 100) |
| `/iter-cap <N>` | Set the per-turn tool iteration cap (1..=1000). Persisted via `SystemConfig`; takes effect on the next user message. On cap-hit the loop emits a warning frame, asks the model to summarize, and terminates gracefully |
| `/iter-cap reset` | Restore the default iteration cap (100) |
| `/show-reasoning` | Show whether live reasoning / chain-of-thought streams to the expression panel (default on) |
| `/show-reasoning <on\|off>` | Toggle live reasoning streaming. When on, the panel renders the model's reasoning in dim italics during a turn (Anthropic `display: "summarized"`, Gemini `includeThoughts: true`, OpenAI-compat already-on); reverts to the operator-set `express` content when idle. When off, providers omit reasoning from request bodies entirely (no token cost) and the panel only shows operator-set expressions. Persists past `ResponseDone` until the next user message |
| `/show-reasoning reset` | Restore the default (on) |
| `/show-tools` | **Console-local.** Show how a tool call renders in the transcript. Web console default `marker`: one dim line per call, `⚙ #17  14:02:11  file_read  0.8s` (`!` and `ERR` on an error) — click it to open the call in the sidebar's Tools tab. Serial TUI default `full`: the whole call under its row, as before |
| `/show-tools <full\|marker\|off>` | The whole call, one marker line per call, or nothing at all (the responses alone). Re-renders the transcript, past calls included; lasts for the console's life. The web console's Tools tab keeps every call's input and result whatever the mode |

## Model

| Command | Description |
|---|---|
| `/provider` | Show active LLM provider, model, and session, the provider gateway when one is stored (`Gateway: on (<url>)` or `Gateway: off (<url> kept)`; see `/local-ai-gateway`), the model wait while Ollama, LM Studio or a native model is active (`/model-wait`), and what the model server is doing while a native model is (experimental) |
| `/provider <anthropic\|gemini\|ollama\|lm_studio\|native>` | Switch provider for future turns. Requires no active session — close the current one with `/close` first. Autonomous in-turn switches queue and apply after the loop completes. `native` (experimental) is a model on this machine and needs one loaded (`/provider --setup native`); a switch away from it leaves the model loaded, and the reply says so |
| `/provider --setup <anthropic\|gemini>` | Add/replace an API key for the named provider without re-running the wizard, then pick its model — multi-turn flow: type the command, then type the key on the next message. Once the key is accepted, a selector offers the provider's models with the current one first (Enter keeps it); the pick persists like `/model` and takes effect on the next message if the provider is active. A slash command at the selector cancels that step and leaves the model unchanged. Auto-targets the missing provider when `<kind>` is omitted |
| `/provider --setup <ollama\|lm_studio>` | Reconfigure endpoint URL, bearer token, and selected model for an OpenAI-compat preset — 4-step flow (Endpoint → Bearer choice → Bearer token? → Model selection). Pre-fills current values; cancel anytime with any other slash command (but for the four the console answers itself and `/stop`). Bearer hot-reloads via `EMBRA_<PRESET>_BEARER` env var (no brain restart). The endpoint may be any OpenAI-compatible server, not just a local one — enter the base URL without `/v1` (`https://openrouter.ai/api`, `https://api.together.xyz`, `https://api.fireworks.ai/inference`, `http://vllm-host:8000`) and the key at the Bearer step; https endpoints keep their implicit 443, only bare hosts and `http://` get the preset's default port. While `/local-ai-gateway` is on, the models are listed through the gateway's `/ollama` or `/lmstudio` prefix and the endpoint typed is stored unprobed as the direct path for when the gateway is off; `none` stores no endpoint, and such a preset answers only while the gateway is on ([Routing the providers through the gateway](LOCAL-AI-GATEWAY.md)) |
| `/provider --setup native` | Pick a native model (experimental): a selector of the catalogue (`qwen3.5-4b`, `qwen3.5-9b`) that says how each one's file stands on this machine. The pick loads the model: embrad starts the model server for it within seconds. A model whose file is not installed is downloaded and checked first; the console follows the updater's lines, the session stays usable, and the model is loaded when the job is done. A native model has no endpoint and no key. `/provider native` switches to it |
| `/model` | Show the active model. Anthropic: the current model and the options. Ollama / LM Studio: the models the server lists (`GET /v1/models` at the configured endpoint, with its bearer; through the provider gateway's `/ollama` or `/lmstudio` prefix while `/local-ai-gateway` is on, so the list is the gateway upstream's) as a selector, the current one chosen; the pick switches the model and keeps the endpoint and bearer (`/provider --setup` changes those); a preset with no direct endpoint has nothing to list while the gateway is off, and the refusal names the two ways out. Gemini: the current model and the options. A native model (experimental): the catalogue as a selector, the model kept loaded chosen, as `/provider --setup native` shows it |
| `/model <qwen3.5-4b\|qwen3.5-9b>` on a native model | Switch the native model (experimental). Persists to `openai_compat.native_model`; embrad ends the model server and starts it for the new model within seconds, and the next message waits for it. A model whose file is not installed is downloaded and checked first, and loaded when the job is done, between turns. Each model keeps its own `/effort` and its own context window |
| `/model <name>` on Ollama / LM Studio | Switch to a model the server lists: the exact name, or the one listed name that matches it ignoring case; anything else is refused with the list. Persists to `openai_compat.ollama_model` / `lm_studio_model` and takes effect on the next user message. The new model runs at its own `/effort` level, or its preset when it has none; the answer says which |
| `/model <opus-5.5\|opus-5\|opus-4.8\|fable-5.1\|fable-5>` | Switch the Anthropic model (on the Anthropic provider; default opus-5). Persists to `SystemConfig.anthropic_model`; takes effect on the next user message — the provider is rebuilt per turn. The `EMBRA_ANTHROPIC_MODEL` env var takes precedence over the persisted value where the brain is given one: a development override, which embrad does not pass in the image. Switching models is a one-time prompt-cache reset (caches are model-scoped). The legacy persisted `opus-4.7` value keeps working but is no longer selectable |
| `/model <gemini-3.1-pro\|gemini-4-argon>` | Switch the Gemini model (on the Gemini provider; default gemini-3.1-pro; `argon` and `3.1-pro` work too). Persists the alias to `SystemConfig.gemini_model`, which the brain maps to the API id (`gemini-3.1-pro-preview`, `gemini-4-argon`); takes effect on the next user message. The `EMBRA_GEMINI_MODEL` env var takes precedence over the persisted value where the brain is given one: a development override, which embrad does not pass in the image. Gemini 3.1 Pro uses the explicit context cache, which is per model; Gemini 4 Argon has none and relies on Google's implicit caching |
| `/effort` | Show the active provider's effort level, its default, and the value actually sent on the wire |
| `/effort <low\|medium\|high\|xhigh\|max>` | Set the effort level for the **active** provider; takes effect on the next user message. Stored per provider (`anthropic_effort`, `gemini_effort`) and, on Ollama and LM Studio, per model (`openai_compat.ollama_effort_by_model` / `lm_studio_effort_by_model`), so neither a `/provider` nor a `/model` switch changes a level you tuned; a model without its own level runs at its preset, and `/effort reset` clears the active model's level. Anthropic: sent as `output_config.effort` (default `max`; lower effort trades depth for latency/cost — relevant on Fable 5, where `max`-effort turns can run many minutes). Gemini: mapped to `thinkingLevel` (default `high`; `xhigh`/`max` send `high`, the ceiling of both Gemini models). Ollama / LM Studio: sent **verbatim** as `reasoning_effort` in place of the per-model auto-map — the accepted set belongs to the model and the server validates; `/effort` warns when the level is outside the set the brain knows for the model (`known_effort_ladder`: Qwen3.8 `low`/`medium`/`xhigh`; gpt-oss and the OpenAI o-series `low`/`medium`/`high`; DeepSeek V4 Pro, DeepSeek V4.1 Flash, GLM 5.3 and Kimi K3 `low`/`high`/`max`; Nemotron 3.5 Super `medium`) and sends it anyway. Unset = the auto-map (`reasoning_effort_for_model`): `xhigh` for Qwen3.8 and `max` for the four Ollama Cloud models, the top of each one's levels, `high` for gpt-oss, the OpenAI o-series, DeepSeek-R1/R2 and the `-thinking` builds; Qwen3.6, Gemma 4 and Nemotron get no field and run at the server's default, thinking on. Each model's levels and default, and the LM Studio build that drops the level: [Reasoning effort](../LOCAL-MODELS/RECOMMENDED-LOCAL-MODELS.md#reasoning-effort). The dev-only `EMBRA_ANTHROPIC_EFFORT` / `EMBRA_GEMINI_EFFORT` / `EMBRA_OLLAMA_EFFORT` / `EMBRA_LM_STUDIO_EFFORT` env vars take precedence |
| `/effort <on\|off>` on a native model | A native model (experimental) has no levels: it thinks first (`on`, the default) or answers without thinking (`off`). Stored per model (`openai_compat.native_effort_by_model`); `low` is `off`, `reset` and any other level are `on`. Sent as `chat_template_kwargs.enable_thinking` with every request, with the model card's sampling for that state; no `reasoning_effort` is sent |
| `/effort reset` | Clear the active provider's stored level (back to its default) |
| `/model-wait` | Show the model wait: how long embraOS waits while Ollama, LM Studio or a native model sends nothing (default 120 minutes) |
| `/model-wait <minutes>` | Set the model wait for Ollama, LM Studio and a native model (experimental), a whole number of minutes, 1 or more. On a native model it also bounds the wait for the model's file to be read at a load. The clock starts when a request is sent and starts again when the answer begins and at each piece of it, so it bounds a silence, never an answer. When it runs out the request is dropped and the turn is cut: the operator's message and the reply so far are saved. **Esc** ends a wait at any time. Persists to `openai_compat.model_wait_minutes`; takes effect on the next user message. Anthropic and Gemini keep their own waits |
| `/model-wait reset` | Go back to the default (120 minutes) |
| `/local-ai-gateway` | Show the provider gateway (WSDS Local AI Gateway's unified listener): whether one is stored, its URL, and whether requests go through it |
| `/local-ai-gateway <url>` | Store the gateway's unified listener and turn it on, once it has identified itself. The URL is normalized (a bare host gets `http://` and `:4000`; `https://` keeps its implicit 443, so give the port; a trailing `/` is dropped; a path is kept; a loopback host, a query or credentials in the URL are refused with the reason), then `GET <url>/v1/models` must answer with the gateway's `x-local-ai-gateway: <version>` header, which every WSDS Local AI Gateway proxy-listener response carries: no answer, or an answer without it (another gateway, a plain model server, an older build), is refused with the reason and nothing is saved; a certificate the brain does not trust is refused naming `/ca import` first (the gateway's CA is imported on the running machine and trusted at once) and then the two routes from outside the OS (`/embra/state/ca-certificates/` with `seed-state.sh --ca-dir`, `Imported_CAs/` before the image is built); a TLS listener given as `http://` is refused naming `https://`. Persists to `SystemConfig.provider_gateway`; takes effect on the next user message (the provider is rebuilt per turn), and the health probe runs through it at once. Every provider request then goes to the gateway with its forced-route prefix — Anthropic `/anthropic`, Gemini `/gemini`, Ollama `/ollama`, LM Studio `/lmstudio` — in the provider's own format and with the operator's own key, which travels to the gateway host in clear over `http://` and covered over `https://`. Ollama and LM Studio keep their stored endpoint; while the gateway is on, the gateway's own `[backends.<name>] upstream` is the server that answers. The first-boot wizard asks for the gateway after the name step, and `/provider --setup <ollama\|lm_studio>` lists the models through it while it is on (the endpoint typed is the direct fallback, `none` allowed). A request the gateway's DLP blocks ends the turn with `HTTP 403: … request blocked by gateway DLP policy (rule …)` (`API error 403: …` on Anthropic); the turn is cut and saved, and `/continue` sends the request again once the gateway lets it pass. [Routing the providers through the gateway](LOCAL-AI-GATEWAY.md) |
| `/local-ai-gateway <on\|off>` | Turn the stored gateway on, after the same identification as `<url>`, or off; the URL is kept. Takes effect on the next user message; the probe runs through the new route at once. `off` names a preset set up through the gateway with no direct endpoint: it answers only while the gateway is on |
| `/local-ai-gateway reset` | Forget the gateway; requests go to each provider's own host from the next user message. Names a preset with no direct endpoint, as `off` does |
| `/embeddings` | Show the local semantic-similarity layer: whether it is enabled, the model, where the model was found (`env` / `state` / `rootfs`), how many vectors the in-memory index holds, how many nodes are embedded, per collection, and the embedding failures since boot (write and query counts, and the last one with its node, reason and time) |
| `/embeddings on` \| `off` | Enable or disable semantic similarity in retrieval. Persists to `SystemConfig.embedding_enabled`; takes effect on the next message. Disabled, retrieval falls back to lexical matching with no other change |
| `/embeddings backfill [--force]` | Embed every node that needs it — missing a vector, or carrying one from a different model. Runs locally (~55 ms/node measured; ~2 min for 2,300 nodes), reports progress, and is resumable: the work set is re-derived from disk on each run. `--force` re-embeds everything |

## Media

| Command | Description |
|---|---|
| `/attach <id\|path>` | Stage an image or a text file for your **next message**. `<id>` is a media id from an image upload; a text upload answers with its `uploads/` path instead (the web console's 📎 button, drag-drop, or paste does the upload and types this command for you); `<path>` is any readable file (absolute, or relative to `/embra/workspace`). An image is normalized (EXIF-rotated, long edge ≤ 2576 px, ≤ 1.5 MiB) and copied into `/embra/workspace/MEDIA/`. A text file (UTF-8, no NUL byte, ≤ 2 MiB) is staged by its path and read when the message is sent: the intelligence gets its path and its text inline (the first 48 KiB; the rest through `file_read`). Staging is per session and survives `/switch` (keyed to the session it was staged in); at most 10 attachments per message, images and files together. Available once the soul is sealed. On Ollama/LM Studio the loaded model must be vision-capable for images |
| `/attach` \| `/attach list` | Show the images and files staged for the active session and the MEDIA store usage |
| `/attach clear` | Drop the staged attachments (the files stay where they are) |
| `/download <path>` | Hand a workspace file to your browser as a download: absolute under `/embra/workspace`, or relative to it; a regular file up to 12 MiB that resolves inside the workspace through any symlink. The browser starts the download at once (the writer tab in the desktop console, the chat view on mobile); the card keeps a link to fetch it again, and the terminal's file line carries the download path. The intelligence does the same with `file_offer` |
| `/media` | **Console-local.** Show the last image in the TUI media pane — a 12-row band under the expression panel (needs a ≥ 30-row terminal). Web console: sixel via xterm's image addon; serial: halfblocks by default, or sixel/kitty/iTerm2 when the host terminal supports it (`EMBRA_GRAPHICS=<mode>` → `embra.graphics=`; `auto` queries the terminal). The chat-mobile UI renders images inline instead |
| `/media off` \| `/media <id>` | Hide the pane, or fetch a specific media id into it |
| `/image-provider` | Show the `image_generate` backend: provider (explicit or default), model, key status (env / dedicated STATE key / Gemini LLM key fallback / not set) |
| `/image-provider gemini` | Use Gemini image models (the only backend today; also the default when unset) |
| `/image-provider model <id>` | Pick the model: `gemini-3-pro-image` (default, 4K-capable), `gemini-3.1-flash-image`, `gemini-3.1-flash-lite-image` (1K only), `gemini-2.5-flash-image` (legacy). Persists to `SystemConfig.image_model`; takes effect on the next `image_generate` call |
| `/image-provider key <token>` \| `key` \| `key remove` | Set a dedicated image-generation key (`/embra/state/api_key_image_gemini`, `0600`, never echoed), show whether one is set, or delete it. Precedence: `EMBRA_IMAGE_API_KEY` env > this key > the Gemini LLM key. The value is masked while it is typed in the console and echoed masked in the mobile chat; it is never shown back. |
| `/image-provider clear` | Reset provider + model to the defaults (the key file is untouched) |

## Git & SSH

| Command | Description |
|---|---|
| `/git-setup <name> \| <email>` | Set git user.name and user.email in the global file under STATE, live for the next git; no arguments shows them. A failed write is reported as such, never as "updated" |
| `/github-token <token>` | Set GitHub token for API access (persists across reboots) The value is masked while it is typed in the console and echoed masked in the mobile chat; it is never shown back. |
| `/git-token <host> <token>` | Set a token for a self-hosted git server (GitLab/Gitea over HTTPS; injected as an `oauth2` rewrite for `git_clone`/`git_push`/`git_pull`/`git_fetch`). No args lists configured hosts; `/git-token <host> remove` deletes. github.com stays on `/github-token`. The value is masked while it is typed in the console and echoed masked in the mobile chat; it is never shown back. |
| `/ssh-keygen` | Generate an ed25519 SSH key pair under the workspace's `.ssh/` and show the public key. The key's comment is the intelligence's name as a lowercase slug at `embraos` (`meridian@embraos`; `embra@embraos` when no name is set), so two instances' keys read apart in an `authorized_keys` file. An existing key is shown, not regenerated (`rotate` replaces it), and keeps the comment it was made with |
| `/ssh-keygen remove` | Delete the key pair after showing its public key and its `SHA256:` fingerprint, the line to take out of `~/.ssh/authorized_keys` on every host that trusted it (the OS cannot revoke it there). An open SSH session is ended first, so no connection outlives the key; the ssh tools are without a key until `/ssh-keygen` generates one; `known_hosts` stays. The handler is the one writer under the workspace `.ssh/`, which the write jail fences for every tool |
| `/ssh-keygen rotate` | `remove`, then a new pair in one step: the old public key and fingerprint to take off the hosts, the new public key to add in their place |
| `/ssh-copy-id <user@host>` | Copy SSH public key to remote host (a private address — RFC 1918 — or loopback, as an address or `localhost`; no other name is resolved) |

## Guardian

| Command | Description |
|---|---|
| `/guardian-define` | **(embra-guardian-v1 — experimental)** Open the multi-line editor to paste a Rust module defining a dynamic tool; validated synchronously **and soul-checked (the replicant check — a `refuse` blocks compilation; the soul outranks even an operator paste)**, then compiled to WASM in the background (poll with `/guardian status <name>`). The check is a call to the model: the console shows `replicant check` while it runs, and Esc or `/stop` ends the wait, in which case nothing is compiled |
| `/guardian list \| status <name> \| show <name> \| delete <name>` | **(embra-guardian-v1)** List dynamic tools (status + declared capabilities; a built tool that is not loaded is marked `NOT LOADED` with the reason), show one's build status + whether it is callable + any replicant verdict + log tail, print its stored source, or remove it (manifest, overlay, project, artifact; a name outside `[a-z][a-z0-9_]{2,39}` is refused before anything is touched). Deleting a tool the image ships (`web_search`, `http_request`, `websocket`) records the decline in `/embra/state/guardian_declined`, so it stays deleted at boot; remove the line, or define the tool again, to have it back |
| `/guardian approve <name> \| reject <name>` | **(embra-guardian-v1)** Approve or reject a tool the intelligence *proposed* via `guardian_propose` (a draft that passed the soul-spec replicant check). Approve compiles it (background build); reject discards the proposal. Only `proposed` tools are affected — built tools still go through `/guardian delete`. Approve asks the model for the replicant check again, and Esc or `/stop` ends that wait: the tool is not built and still waits for approval |
| `/guardian rebuild <name> \| --all` | Build a tool again from the module on record — for a built tool an OS update left unloaded (the in-OS toolchain changed), for one whose artifact on DATA is not the one its record names or was built before the record kept the hash, and for a failed build (`/guardian list` marks the first two `NOT LOADED` with the reason, and a failed build `Failed`). `--all` queues every such tool and builds them one at a time in the background. The stored module passes validation and the replicant check again before it compiles: a `refuse` blocks, a check that cannot run fails closed, and the reason lands in `/guardian status <name>`. The rebuild of one tool waits for the check as `/guardian-define` does: the console shows `replicant check`, and Esc or `/stop` ends the wait with the tool not rebuilt and its record as it was; `--all` checks in the background. Proposals are never built this way — they need `/guardian approve` |
| `/guardian key brave <token>` | **(embra-guardian-v1)** Set the Brave Search API key host-side (STATE, `0600`) to enable `web_search`-capable tools, the shipped `web_search` first among them; omit `<token>` to check status — the key is never echoed, never in a guest module, the manifest, or results. The value is masked while it is typed in the console and echoed masked in the mobile chat; it is never shown back. |
| `/guardian secret <host> <header> <value>` | Store a credential the host adds to every `http_request` to that host on its port and to the handshake of every WebSocket connection there (the guard sets the header on a hop whose host and port match and on no other: a host stored without a port is port 443, and `<host>:<port>` names another port, a secret of its own); a tool never sees it, and it never enters a tool's input, the turn trace or the session history. Stored in `config.system`, like git tokens. `/guardian secret` lists hosts and header names (values are never shown); `/guardian secret <host>` shows one host's; `/guardian secret <host> remove` forgets a host's secrets; `/guardian secret <host> <header> remove` one header; either closes the WebSocket connections open to that host and says how many. A tool may not set `Authorization`, `Proxy-Authorization` or `Cookie` itself. The value is masked while it is typed in the console and echoed masked in the mobile chat; it is never shown back. |
| `/guardian egress allow <host> \| deny <host>` | The allowlist of private hosts the Guardian tools may reach (`http_get`, `http_request`, `websocket`): a name with its subdomains, or an IP literal. | `/guardian connections \| connections close <id> \| connections close all` | The WebSocket connections the Guardian tools hold open between calls (the shipped `websocket`, and any tool with the capability): one line each with the id, the tool, the host and port with the path (never the query), how long it has been open and unused, the frames waiting and the frames dropped. `close <id>` ends one and `close all` every one.
